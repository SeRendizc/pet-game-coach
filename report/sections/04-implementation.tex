\section{实现中的难点}

这一节的主线是\textbf{把「算」和「说」分开：引擎负责对，模型负责讲。} 下面几个取舍都是这条主线的推论，也都是我改错过的地方。

\subsection{一条执行链，和它每一步的成色}

三种角色共用同一条链：玩家提问、或代码判定该开口时，请求先过门控，再由有界的工具循环去查证，查到的回执必须过校验，最后才允许输出——或者允许沉默。

链上七步逐条核过，依据都在仓库里：门控在 \code{policy.js}，循环、校验与输出上限都在 \code{runtime.js}，工具与参数契约在 \code{toolbox.js}，证据来自 \code{engine.js} 的合法行动枚举与 \code{strategist.js} 的 93 张知识卡，记忆写在 \code{memory.js}。\textbf{只有记忆那一环是「部分」}：计数与规则已实现，Generative Agents 式的 Reflection 合成仍是设想。还有一处必须说准，否则会把单工具记录包装成多步 Agent：\textbf{有界循环已实现，并由确定性 planner 测试验证，但真实模型评测中还没有观察到多工具链}——44 条既有真实记录的调用次数分布是 $\{0{:}36,\ 1{:}8\}$，本轮又补跑 4 条不同问法的用例，全部不超过 1 次。

\subsection{数字不能让模型算}

第一版我让模型看着局面直接给建议，回答里的数字稳定地错：编出不存在的技能名，算错伤害，在两个都能击倒的技能里挑面板数字大的那个。改法是把职责切开：引擎枚举，模型解释。

同一个残血目标，火花直接伤害 52，追猎 75，两者都够击倒，都耗 2 点能量。只看面板，很自然会建议选追猎。但这是错的：追猎的额外伤害来自「目标已灼烧」这个前提，对方吃药、换宠、防御都会让前提失效。这种判断交给模型是猜，交给枚举是算。

切开之后还剩两类数字校验抓不到的错。第一类是道具名：游戏里只有回复药、净化药、能量果三样，模型会把净化药说成「解药」、能量果说成「以太」——数字全对，引用全对，只有名字是错的，因为没有数字可校验。第二类是因果：伙伴倒下时，它这一回合已经排好的行动会被取消，模型会把这次取消描述成「命中了」。两类都靠新增检查解决：一份别名黑名单，命中即判不合格；读回合事件，某个行动被记为取消时，正文里就不能出现它造成了伤害。

最后一类更隐蔽：模型读到的规则本身是旧的。原来的属性相克表不对称，我换成两个独立的三环；军师、经验层、规则页从同一张表读，自动跟着走了，但把规则抄成自然语言的副本不会。改掉手写的那张边界卡之后，扫第二遍才发现六张脚本生成的属性卡里仍是旧数值——它们正是检索喂给模型的地面事实：教练会照着一张引擎已不再实现的规则回答，而测试全绿，因为没有测试盯这句话。根因是那句话在生成脚本里硬编码，这一轮改成从规则对象取数。这类副本我手工找漏了三次。

\subsection{「该不该调工具」不该由模型决定}

工具决策我做过三轮真实评测，同一套 44 条预注册用例，全部真实 API 调用，变差的那一轮也保留。三轮依次改的是：原始提示词；把「默认停止」写进提示词并点名哪几类必须调；给模型加一个「必须调用」的字段。第三轮已回退。

第 2 轮不是纯改善：多余调用从 75.0\% 降到 33.3\%，漏调却从 0 升到 21.9\%。第 3 轮更差：我加那个字段本意是补上三类硬需求，实际等于告诉模型「这个字段是空就不必调」，而它在大多数用例上都是空的。

三轮的摆动说明问题不在措辞，在分工。数据给出的分界很清楚：模型\textbf{选哪个工具}很准（第 2 轮在「预期应调且确实调了」的 12 条上是 12/12），但\textbf{判断该不该调}只有一半正确。所以第 4 轮不是继续改提示词，而是把政策写进代码：证据包里已经带着当前局面和最近回合事件，问当前状态的不用再查，只有结构上不含的四类才需要查；判定需要时由代码直接执行第一步，再问模型要不要继续，判定不需要时整个工具循环跳过。

44 条里只有 32 条可判定，每格 1 条、单次运行，上表所有差值都没有置信区间；即使第 2 轮，严格正确率也只有 50\%。而且这 50\% 里有一部分不是模型错——预注册标准认为「我这只还剩多少血」应该调一次读状态，但证据包里本来就带着当前局面，第 2 轮那 7 条漏调里有 6 条属于这一类，是两种政策的差异。产品必须选一个并说清楚，我选了「包里已有的事实不重复取」。

\subsection{检索没有赢过关键词}

我的假设是：在词项检索之上再加一层领域概念扩展，口语化提问的命中率会提高。为了验证它，我建了一个四臂对照：不检索；词项检索（中文二元词项加权 + IDF）；词项加领域概念扩展；以及一个把反例文本提为一等字段的第四臂。128 条查询（112 条有正解、16 条越界），离线跑，不调用模型。

四臂都是本机可查的词项方法，\textbf{没有一个用到向量}——领域概念扩展是一份可审阅的领域词表，不是预训练 embedding。仓库里另有一个真正的多语言向量检索实现（Python 侧 \code{semantic-worker.py}，用 \code{model.encode} 编码知识卡），它不在这组 128 条实验里，两者的数据集与实现都不同，不能混在一张表里比较。

结果是没有一个臂显著赢过关键词基线。最好的一臂只高 2.68 个百分点（112 条正解里 5 胜 2 负），McNemar 精确检验 $p = 0.4531$，配对 bootstrap 95\% 置信区间 $[-1.79, +7.14]$ 个百分点，跨零。

我差点在这儿犯错：看到扩展没赢，第一反应是「检索没用，RAG 是伪需求」。拆开四臂才发现不是——第四臂的 MRR 从 0.8007 升到 0.8244，排序确实变好，只是改善都发生在 112 条正解上。最后我记成「这次测量没测出差别」，既没换成向量检索，也没宣称 RAG 无效。

真正被这轮测出来的是负例拒答：三个检索臂都只有 9/16，越界提问仍然召回了卡片，原因是词项检索只要命中任意二元组就判为正分，没有最低分阈值，也没有拒答机制。这是尚未解决的问题，调权重解决不了。另外，这 128 条查询和标注都由我完成，不是独立盲标集：沿用的 20 条旧查询 Hit@3 是 81.25\%，新写的 92 条是 93.48\%，说明出题时我已知道卡片里有哪些词，所有绝对数字都偏乐观。

\subsection{玩家不打开聊天，就等于没有教练}

第一版做出来我自己试了两局，发现小芽的全部能力都在聊天面板里，而我全程没有打开过那个面板。改法是把主入口挪到游戏事件上：开局和关键风险变化时，战斗页底部出现一行短提示，解释收在二级入口里按需展开；玩家出招之后旧提示立刻隐藏，等新局面重新评估。

副作用是提示一多就变成噪音，门控反而比内容更难做：玩家是否在前台、是否已出招、是否已忽略过、本回合是否已提示过、上次提示距今多久、当前风险是否可行动，逐项判断；每局总量、同类只出一次、冷却时间各有上限，老师和军师共用同一份每局配额。

这条通道还有一个口径问题：判断玩家是否掌握某个知识点时，只用他没有被提示过的时候做出的选择（文献里的 assistance dilemma，见第二节）。

\subsection{对手交给模型，引擎只列合法行动}

题目场景是 PVP，我最初的做法是让引擎的启发式当对手：轻松档随机，标准档优先伤害和治疗，挑战档枚举双方合法行动并比较一回合结果。这一轮改了——\textbf{对手的决策交给模型，引擎只负责列出有哪些合法行动}。

改的理由不是「这样显得对手更聪明」——这个类型里决定胜负的是搜索和训练，不是语言能力。上一条结论回答的是「谁更强」，这一轮要解决的是「对面得是个人」：按伤害公式调出来的启发式，出招永远挑不出毛病，也永远不像人。

难度因此改成只控制「给对手多少帮助」，不控制谁在决策：简单档只给合法行动列表，标准档多给一句对手自己教练的建议，挑战档再给出这一回合的枚举分数。对手那个「自己的教练」不是另写一套，而是拿同一份军师推理函数把双方对调后跑出来的（图~\ref{fig:pvp-split.png}）。

\shot[0.70]{pvp-split.png}{本地双人分屏：两侧各一块行动面板、各带一条教练，跑的是同一个推理函数，只是局面左右对调}

兜底只在四条路径上出现：模型未配置、模型选了列表外的行动、超时（上限 4 秒）、网络错误；四条各有测试，且都必须在没有后端、没有密钥的前提下工作。本次干净跑里四条都没有被真实流量碰到（兜底 0 次），因此并发压力下这条链路的上限如何，我没有测过。

\textbf{胜率这一项我没有测出结论}。正常节奏下玩家每回合等待 0 毫秒——对手思考的那一秒被玩家自己的思考时间吸收了；但把 24 局放在一起看，四个格子两边的胜率是 100/100、100/100、66.7/50、50/50，\textbf{对手一局都没赢过}。准确的说法是：n=6 而且对手全败，这套对照既不能支持「对手变强了」，也不能支持「打平了」，只能说没有变弱的迹象。

同一件事上我自己改错过两次。题目要求军师在对战场景给建议，我的第一版判据却是「只要是对局模式，教练一律不介入」，还把它写成「公平性设计」当亮点——等于把主功能在题目指定的场景里禁用了。第二次改成「对手是真人时闭麦、是电脑时照常」，又不自洽：电脑对手存在的意义就是模拟真人，行为就该一致。最终改成本地对战一律允许教练，只保留线上竞技的闭麦开关；底线不是「整局不说话」，而是「不读取对方待执行的动作」，那条一直没破，也有测试。
