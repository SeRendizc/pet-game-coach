对应清单原文：`C17 残局提示实际长局浏览器触发、慢模型并发和不同窗口尺寸完整验收；目前残局判定有自动测试，不能据此声称真实游玩全覆盖。`

**本报告只覆盖其中「残局提示的长局浏览器触发 + 不同窗口尺寸」这一半。慢模型并发不在本次范围内（由他人负责）。**

## 0. 结论摘要

- 用 headless Chrome + CDP 真实打开 http://127.0.0.1:8765/ ，在页面上真实走完「营地 → 出征页选关卡/选队伍/选难度 → 开始训练 → 逐回合点行动」的完整流程，共打了 **8 局 PVE，每局 14～17 回合，全部打完整场（无截断、无未结束）**。
- 这 8 局里 **8 局都真实触发了残局提示（`#attention-cue`），每局 1 次，共 8 次**，触发时双方在场宠物血量都 ≤ 35%，且我方存在一击伤害 ≥ 对方剩余 HP 的攻击 —— 与 `coach/experience.js` 的 `decisiveOpportunity()` 条件一致。
- 触发有两条互相独立的记录且完全对齐：**页面 DOM 上抓到的提示原文** + **app 自己写进 `localStorage['xiaoya-memory-v1']` 的 `channel:'endgame'` 日志**（条数、回合号一一对应）。
- 两个窗口尺寸（**1440×900** 与 **390×844**）各打同一套 4 局：提示在两种尺寸下都 `inViewport=true`、8 个取样点全部命中提示条自身、`occluded=false`（没有被任何其它元素盖住）、`display:flex / visibility:visible / opacity:1 / z-index:15`、`hidden=false`。窄屏截图见 `reports/c17/390x844-game1-meadow-turn9-endgame-cue.png`。
- **重要前提（务必先读第 6 节）**：实测期间，**正在跑的那个服务进程不提供 `/rules.js`（HTTP 404）**，而 `app.js` 已经 `import {rulesSections} from './rules.js'`，导致页面 **一行 JS 都不会执行**。本次实测没有改仓库文件、没有重启服务，只在浏览器网络层把这个磁盘上真实存在的文件补上（sha256 已记录，与磁盘文件一致）。这不是残局提示逻辑的问题，但它意味着「照现状用真浏览器打开这个 Demo 是坏的」——`server.js` 的白名单后来已经补上了 `rules.js`，但**进程不重启就仍然 404**。

## 2. 方法

1. **真实点击**：所有按钮都用 CDP `Input.dispatchMouseEvent`（mousePressed/mouseReleased）点，坐标取自 `getBoundingClientRect` 并先 `scrollIntoView`；点之前做命中测试（`document.elementFromPoint`），命中失败才退化成 `el.click()` 并记录。本次记录在案的 **136 次局内行动点击全部是真实鼠标事件**（`method:"mouse"`，0 次退化），其中 120 次是技能、16 次是倒下后的免费补位；开局流程的点击（关引导弹窗、`#go-pve`、关卡、队伍增减、`#start`）同样走真实鼠标事件，未计入这 136。
2. **真实流程**：打开首页 → 关掉首次引导弹窗（选「关键时搭把手」＝`gentle`，不能选 `quiet`，否则按源码提示不会显示）→ 点 `#go-pve` → 选关卡 `#stage-picker [data-stage]` → 用 `#roster [data-pet]` 增减宠物凑成目标队伍 → 设 `#difficulty` / `#seed` / `#speed` → 点 `#start`。4 局用的种子依次是 17 / 18 / 19 / 20。
3. **打法**：每个回合点击 `#actions` 里**第一个未禁用的行动按钮**（技能页按配招顺序取第一个合法技能；`#phase` 为「请选择补位伙伴」时取第一个换宠按钮）。等价于「一直点第一个技能」——本次实际点到的技能只有 3 种：`疾爪`（烬尾狐的先制 0 消耗技）、`撞击`（无消耗稳定攻击）、`砾石弹`（砾背獾的第一个技能）。**没有用 `page.evaluate` 改任何游戏状态来伪造残局**——脚本对页面的写操作只有三类：三个设置项（难度/种子/播放速度，等价于玩家在界面上改设置）、`scrollIntoView` 把要点的元素滚进视口、以及为安装只读探针而注入的一段读 DOM/localStorage 的代码。
4. **记录**：每回合读一次 DOM（`#turn` / `#phase` / `#player`、`#enemy` 的在场宠物名字与 `HP / maxHP` / `#log` 首行 / `#result`），并在页面内注入一个只读探针，每 100ms 采样 `#attention-cue` 与 `#live-coach` 的「可见性 + 文本」，只要出现新的可见文本就带时间戳、回合标签、双方 HP 记一条。探针只读 DOM 与 localStorage。
5. **两条独立证据**：①页面上抓到的提示原文；②app 自己写的 `channel:'endgame'` 教练日志。报告里两者分开列出，条数与回合号对齐才算数。
6. **遮挡检查**（`cueGeometry()`）：读 `#attention-cue` 的 `getBoundingClientRect`、`getComputedStyle`，判断是否完整落在视口内；在圆角矩形内缩 16px 取 8 个点做 `document.elementFromPoint`，把命中结果分成「提示条自身/其后代」「提示条的祖先」「外来元素」三类——**外来元素不为空才算被遮挡**。
7. 每个视口都用一个**全新的 Chrome profile**（独立 `--user-data-dir`），所以本地成长（localStorage 里的等级/训练点）不会跨视口累积，两个视口打的是同一套对局、都从 Lv.1 开始。

复现命令（脚本把完整 JSON 打到 stdout，另有 `--json-out=` 可存文件；本次的原始 JSON 在 `/tmp/c17probe/final.json`，未放进仓库）：

```bash
node scripts/cdp-long-game.js --games=4 --viewport=1440x900 --viewport=390x844 --verbose \
  --json-out=/tmp/c17-final.json
```

## 4. 观察到的现象

1. **残局提示在真实长局里确实会触发**：8/8 局，每局 1 次，且都出现在「双方在场都残血、我方有一击必杀手段」的那一回合（第 9～13 回合之间）。
2. **触发点总是出现在我方还能收尾、但对手也还没死的窗口里**：4 种触发的敌方 HP 分别是 8 / 6 / 20 / 21，我方主动技能（撞击）伤害 23 / 24 / 22 / 22，因此提示里的「算 N 伤害，对方 M HP」在 4 次里都是真的能一击收掉（N ≥ M）。
3. **提示出现后不会挡住操作**：提示条是 `position:fixed` 居中在底部、`z-index:15`，宽屏 640×64、窄屏 358×106；8 个内缩取样点全部命中提示条自身，没有外来元素覆盖，也没有超出视口。窄屏下它压在战斗记录上方，但自身完整可读、可点（右上角有 × 关闭键）。
4. **同一局里没有出现第 2 次残局提示**：8 局都只触发 1 次。这既可能来自「同一对宠物只提示一次（`tacticalShown`）」也可能来自「本局的残局窗口只出现了一次」——本次数据不足以区分这两者（见第 7 节）。

## 6. 必须先读的环境偏差：`/rules.js` 404 让整页 JS 不执行

实测开始时发现：正在跑的服务进程 **不提供 `/rules.js`**，而 `app.js` 第 11 行已经 `import {rulesSections,ruleFacts} from './rules.js'`。后果是模块图整体加载失败，**页面一行 JS 都不执行**：实测中首页没有伙伴卡片、`#wallet` 为空、首次引导弹窗也不出现（因为 `showModal()` 根本没跑到）。

证据（本次实测记录）：

```
curl -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/rules.js   →  404
curl -o /dev/null -w '%{http_code}' http://127.0.0.1:8765/app.js     →  200
页面表现：#camp-roster.innerHTML.length = 0，#wallet 文本为空，#coach-welcome[open] = false
```

原因：`server.js` 用一份硬编码白名单 `publicAssets` 提供静态文件。实测开始时（19:04 复核）白名单里没有 `rules.js`；**19:09 再次复核时白名单已经包含 `rules.js`（别人补的，server.js mtime 19:01），但正在跑的进程仍然 404 —— 它是在那次改动之前启动的，内存里还是旧白名单，必须重启进程才会生效**。

按任务约束，我**没有修改 `server.js`、没有修改 `app.js`、也没有重启任何服务**。为了让「真实游玩」这条测试能跑起来，脚本在浏览器网络层做了透明补齐：CDP `Fetch.enable` 拦截 `/rules.js` 请求，用 `Fetch.fulfillRequest` 返回**磁盘上那个真实文件**的内容（不是我自己编的替代实现）。

- 补齐的文件：`/Users/serendizc/Desktop/pet-coach-game/rules.js`
- 字节数 14596，sha256 `2b93cd245ebb0e2781244ff5909800031f10a9a08a4025ad299bd8d7b09a3a0a`（两个视口各补齐一次，哈希相同；与 19:09 复核磁盘文件的 sha256 完全一致，说明喂给浏览器的就是原文件）
- 补齐模块列表是脚本从 `app.js` 出发自动走 import 图找出来的（`findUnservedModules()`）：凡是「服务器 != 200、磁盘上存在」的模块才会被补齐；如果服务端已经能正常提供，脚本不会启用任何拦截（此时 `--no-shim` 与默认行为等价）。

**因此本次实测的结论要这样读**：游戏逻辑、引擎、教练判定、页面 UI 全部来自服务进程提供的原文件；只有 `rules.js`（规则弹窗文案模块）这一个文件是经 CDP 从磁盘直接喂给浏览器的。如果只看「残局提示是否在长局里触发」，这个偏差不影响结论（`decisiveOpportunity` 在 `coach/experience.js`，由服务器正常提供）；但它确实意味着**这次不是 100% 原样端到端**。

**建议**（不在我的改动范围内）：重启一次游戏服务，让 `publicAssets` 里新增的 `rules.js` 生效；否则现在任何人用浏览器打开这个 Demo 看到的都是一个不工作的页面。

## 7. 这次实测没有覆盖的部分

1. **只测了 PVE 训练**。没有测 PVP（`AI 模拟真人` 与 `真人同机分屏` 都没打），也没有真人对手、没有真人对局的沟通/公平性场景。

3. **打法是脚本固定点第一个合法行动**，不是人类打法：不用道具、不主动换宠、不防御，8 局全负。人类玩家会治疗/换宠，残局窗口出现的时机和次数会明显不同。因此「什么时候触发」这部分只代表这一种打法。
4. **没有测慢模型并发**（明确不在本次范围）：本次没有触发任何模型请求，也没有在模型慢/超时的情况下观察提示时序。

6. **没有测提示的自动隐藏**：截图是在出现后约 1 秒内拍的，没有等到 12 秒去验证它是否自动消失。（12 秒这个数字来自源码 `app.js:383`，不是本次实测值。）
