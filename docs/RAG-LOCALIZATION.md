# 小芽本地战术知识库与 Agent 接入方案

更新：2026-09-16。当前交付：离线检索工具基础与测试；尚未接入线上聊天/自动提示，不代表完整 RAG 或 ReAct 已验收。

## 为什么借鉴宝可梦

宝可梦官方对战指南讨论了速度与特殊先手、主动换宠的行动成本、治疗时机以及队伍属性覆盖。这些适合借鉴为“先问哪些问题”的战术思路。其具体倍率、双属性、特性及逃跑规则不能沿用到小兽训练场。

来源：[宝可梦官方对战指南](https://diamondpearl.pokemon.com/en-gb/trainersguide/fundamentals/battling/)，访问日期 2026-09-16。没有整篇搬运攻略；本地战术卡自行编写，数值依据 engine.js / progression.js。外部来源仅作为思路出处，不作为本地规则权威。

## 当前落地

- `knowledge/tactics.json`：11 张卡，包含版本、标题、关键词、战术原则、反例、所需证据、本地权威文件和启发来源。
- `knowledge/sources.json`：来源用途与本地化边界。
- `coach/retrieval.js`：中文双字切分、少量口语同义词、加权词项匹配；按游戏和版本过滤，限制返回条数与字符预算。无命中时返回缺证据，不硬塞攻略。
- `buildKnowledgePacket`：附带当前合法攻击的普通/防御伤害，直接调用引擎。明确只算静止目标的直接伤害，不等于胜率，也不含对手将要执行的动作。
- `knowledge.test.js`：6 个测试，覆盖口语、版本/空结果/预算、外部机制隔离、溢出伤害、合法技能/PVP、无战斗数据场景。

执行：`node --test knowledge.test.js`。当前 6 项通过，仅证明这些固定用例；不能推断真实模型回答准确率。

这是可审查的关键词检索基线，不是语义向量检索。字符预算也不等于后续的 token 预算。当前本地函数的 PVP 拦截不是服务端竞争公平性的完整保障。

## 接入后的 Agent 怎么工作

以“狐面对已灼烧的残血鹿”为例：

1. 事件产生任务，绑定 battleId、decisionId、stateVersion、rulesVersion、deadline。
2. 快速模块先判断是否有提示价值。玩家已掌握该知识点、无明显风险时允许保持沉默。
3. Agent 查当前可见状态，按需要检索“灼烧联动”“够用的伤害”，而非每次灌入整本攻略。
4. Agent 调比较工具，必要时模拟防御、治疗、换宠等候选分支。工具报告假设与范围，不暴露敌方已选动作。
5. 检查当前状态仍有效、建议可执行、数字可追溯；再决定是否呈现一句话或继续观察。
6. 记录玩家实际选择与结果，复盘时再讨论原因。没采纳不自动算差评，也不自动判玩家不懂。

例如同一目标 50 HP，一级狐对灼烧鹿，火花直接伤害52、追猎75，都耗2能量。两者都满足未防御且未治疗的击倒条件。只有进一步比较对手分支才可能说明某招更稳；不能仅因75大于52提醒玩家“打错了”。这会作为重要的反例评测。

## 让 RAG 更聪明的下一步

1. **补规则结构层**：由 SKILLS、SPECIES 和结算代码导出可核对规则；手写说明变更必须经测试。未来将统一规则版本源，避免手改常量漏同步。
2. **补状态适用性**：当前卡片的 requiredEvidence 是文字声明。下一步转为明确字段，检查是否有灼烧、是否有技能、资源是否足够等；检索命中不代表适用。
3. **混合召回**：保留当前词项基线，再加入中文向量检索。规则版本和模式先过滤，之后排序；用真实口语问法评测改善，不能只换技术名。
4. **证据重排与反例配对**：推荐“先挂状态”时，同时召回“残血直接收尾”；模型必须说明本局为什么满足前提。
5. **分支计算工具**：接共享结算器，返回数值和假设。RAG 不负责心算，模型负责选工具、理解取舍与解释。
6. **证据验证**：输出引用 skill/card/turn 的 ID，检查引用是否真的支持结论；缺数据就补取，超时则放弃当前实时输出。
7. **外部记忆与32K测试**：原始回合证据按ID保存；上下文仅取任务需要的片段，摘要不能替代数值证据。状态快照、工具回执与长时偏好分开。
8. **玩家适应与RL**：学习何时提示、提示到哪层。先固定正确性与公平性门槛，训练干预策略；比较不干预、固定规则、学习策略。不能把“用户照做”作为唯一奖励，也不能将此声称为LLM权重训练。

## 游戏数值优化方向

优先让现有宠物产生可解释的选择，暂不堆种类。狐承担快速铺状态与收尾，狮承担破防与爆发；评价二者不能只看生命和攻击总和。检查同等培养预算下，谁擅长哪些局面、付出什么代价、对手如何反制。

首批平衡场景：满血/残血、快/慢、防御/不防御、低/高能量、药品有/无、可换宠/最后一只。统计支配动作、双方存活、资源消耗和回合长度，并查看具体失败轨迹。少量种子不当平衡结论。

培养以跨阈值为目标：速度从落后到平速与超过是两种结果；加攻击是否少打一回合；加生命是否多承受一次攻击。先按这些结果调整数值，再更新教学案例。

新增宠物、属性、配招与天气继续按 GAME-EXPANSION-PROPOSAL 分阶段讨论。每引入一种机制，都要同时有可用战术、反制方法、知识卡、计算支持和测试案例。关闭小芽后游戏仍需可理解，不能靠故意难懂来证明AI有用。

## 优先级

下一步优先把“事件触发 → 有界工具调用 → 证据核验 → 克制提示 → 本回合结果复盘”接成一个真实闭环，然后补个性化和训练实验。检索工具只是其中一环；不以知识卡数量作为Agent完成度。

## 第二轮更新：已接入军师（2026-09-16）

以上“离线未接入”的描述是首轮状态。本轮知识卡扩至30张；检索与构建证据的实现移至 coach/strategist.js，coach/retrieval.js 保留兼容导出。通过 npm run build:knowledge 从JSON生成 content.js 中的浏览器数据，测试确保两份一致。客户端即时军师与服务端军师均能把卡片加入证据，真实DeepSeek质量尚未测量。

新增分支证据来自共用结算器的一回合穷举：平均启发式分、最坏分、对方主动换宠时最坏分。不会将过去的换宠行为当作未来确定动作。挑战电脑连续主动换宠额外承担6/12/18分惯性成本，属于待校准的行为策略，不是禁止换宠的游戏规则，也不是纳什均衡求解或RL。

能量数值暂时保留，先补界面说明与回归测试；后续比较耗4技能净耗3是否形成过强防御循环，再决定调参。速胜试行每关首次10回合内胜利加1训练点，其余基础奖励不变；需检验成长碾压和不同打法的完成难度。

下一步优先对30张知识卡编写更多不同局面的适用/不适用测试，并将固定检索升级为有界工具选择。单纯增加知识数量无法证明增益，需要盲测问题、分支正确性和无检索对照。
